# NO SIGNAL

Мобильный редакционный журнал: альбом дня, маршрут из 60 пластинок, заметки к трекам, личная полка и опциональная облачная синхронизация.

## Фронтенд
- Адаптивный интерфейс для iPhone и desktop, PWA и service worker.
- Архив: поиск, фильтры по этапам, сортировка.
- Deep links и навигация браузера для выпусков.
- Локальные сохранения, реакции, история открытий.
- JSON-экспорт/импорт личной полки.
- Альбом дня по локальной дате; при настроенном облаке опубликованный выпуск из базы имеет приоритет.
- Редакторская форма назначения выпуска на дату (для пользователей с ролью editor/admin).

## Облачный backend (Supabase)

В репозитории лежат схема PostgreSQL, RLS-политики, seed-маршрут и клиентский адаптер. Пока не указаны параметры проекта, сайт продолжает работать локально.

### 1. Создать проект
Создай проект в Supabase Dashboard. Не передавай секреты в чат и не добавляй service-role/secret key в клиентский код.

### 2. Создать таблицы и загрузить маршрут
В Supabase → SQL Editor выполни по очереди:
1. supabase/schema.sql
2. supabase/seed-route.sql

Seed добавляет метаданные всех 60 альбомов, необходимые для связей и публикации выпусков. Полные редакционные материалы остаются во фронтенд-каталоге и требуют отдельной редакторской проверки перед переносом в базу.

### 3. Настроить публичный клиент
В Supabase → Project Settings → API скопируй Project URL и anon/public (или publishable) key. Заполни в backend-config.js параметры supabaseUrl и supabaseAnonKey.

Эти два значения предназначены для браузерного клиента. Никогда не используй service_role или secret key. Изменения в GitHub Pages публикуются автоматически после push в main.

### 4. Создать аккаунт и назначить администратора
Открой сайт → «Манифест» → «Твоя полка в облаке» и создай аккаунт. Если в настройках Supabase включено подтверждение почты, сначала подтверди адрес.

Затем в SQL Editor выполни запрос, подставив свой email:

    update public.profiles
    set role = 'admin'
    where email = 'YOUR_EMAIL';

Не выдавай роль admin другим пользователям. Редакторская панель доступна только ролям editor и admin; операции дополнительно ограничены RLS на стороне базы.

### 5. Проверить работу
- Войди в аккаунт и нажми «Синхронизировать мою полку».
- Открой редакторскую панель и назначь альбом на сегодняшнюю дату.
- Обнови главную: если выпуск опубликован и существует в локальном каталоге, он должен появиться вместо автоматического выбора.
- Для пользователя без аккаунта доступен локальный режим.

## Структура backend
- supabase/schema.sql — таблицы, триггер профиля, роли и RLS.
- supabase/seed-route.sql — начальные записи 60 альбомов.
- backend-config.js — только публичные параметры подключения.
- backend.js — auth, профиль, синхронизация личной полки, загрузка/публикация выпуска.

## Ограничения текущего этапа
- Настоящий cloud backend требует создать и настроить Supabase-проект; эти действия нельзя выполнить только изменением репозитория.
- В текущей схеме нет платёжной системы, публичных профилей, аналитики и полноценного CMS для редактирования всех полей альбома.
- Не все описания/трек-листы прошли внешнюю верификацию; редакционные интерпретации нужно отличать от проверяемых метаданных.
- Supabase JS загружается через CDN при первом использовании облачных функций, поэтому вход и синхронизация требуют сети. Основной локальный каталог продолжает открываться без неё.

## Публикация и iPhone
GitHub Pages публикует сайт из main. После обновления открой сайт в Safari и перезагрузи страницу. Если приложение уже добавлено на экран «Домой», старый service worker может обновиться не мгновенно.
